Abstract

This project investigates which content items should be prioritized for human review when content teams have more pages than they can inspect at once. The analysis uses FlyRank Search Intelligence data and observed search, visibility, click-through, engagement, and trend signals to build a repeatable prioritization workflow. A transparent baseline action score is created first and then compared with a machine learning model using the same grouped validation design. Potential leakage is checked by excluding identifiers and target-derived fields from the predictive feature set. The final result is a ranked recommendation queue with reason codes intended for decision-support rather than proof of causality or guaranteed refresh impact.

1. Introduction / Problem Statement

Content teams often manage more pages than they can realistically review. As a result, deciding where to spend editorial effort becomes a prioritization problem.

This project develops a repeatable workflow that ranks content items using observed Search Intelligence signals. The purpose is to help identify pages that may deserve earlier human review.

Decision supported: The output helps a content team decide which pages to inspect first. It does not automatically decide that a page must be refreshed, rewritten, removed, or changed.

2. Data

The project uses the FlyRank ML Internship Search Intelligence dataset. The dataset contains content-level observations with search demand, competition, content characteristics, click-through rate, average position, engagement, scrolling behavior, and observed trend signals.

Unit of analysis

One row represents one content item identified by content_id.

Modeling target

The continuous target used in the modeling workflow is trend_pct. This represents an observed trend percentage in the dataset.

Fields excluded from prediction
  • content_id — identifier only and not a meaningful predictive signal.
  • client_id — used to create grouped validation splits rather than as a predictive feature.
  • trend_pct — the target variable.
  • trend_direction — excluded because it is closely related to the target and creates a leakage risk.
  • Duplicate or derived tier fields — excluded when they directly bucket underlying numeric measurements already available as features.
Public-safe data rule: No client names, domains, private URLs, private queries, credentials, or raw private exports are displayed in this research paper.

3. Methodology

Feature engineering

Numeric variables are handled using median imputation. Categorical variables are handled using missing-value treatment and one-hot encoding. Identifiers and target-derived variables are excluded.

Baseline action score

A transparent baseline score combines safe observed signals such as click-through rate, average position, engagement, and search demand. The score creates an interpretable ranking and reason codes for human review.

Machine learning model

A Random Forest regression approach is used to model the continuous trend target. The model can capture non-linear relationships between the available features and the observed target.

Validation design

The train/test split is grouped by client_id so that the same client group is not used simultaneously for both training and evaluation. This is intended to reduce overly optimistic performance caused by client-level similarity.

Leakage checks

Identifiers, target values, and target-derived fields are excluded from the predictive feature set. The analysis also checks whether included features are available at the intended prediction moment.

5. Limitations & Honest Framing

Observational data

This analysis uses observational data. It can identify measured patterns and associations but cannot prove that refreshing or changing content causes a specific outcome.

Missing context

Editorial quality, seasonality, competitor activity, business priorities, and other external factors may not be fully represented in the available data.

Model limitations

Machine learning performance depends on the available features, target definition, and validation design. Performance on a future or different dataset may differ.

Honest framing: Observed · Measured · Directional · Decision-Support

7. Reproducibility

The project is structured as a sequence of notebooks covering data contracts, feature design, leakage checks, signal auditing, baseline scoring, model development, evaluation, and ranked recommendations.

  1. Define the unit of analysis and target.
  2. Classify fields as features, labels, context, or excluded variables.
  3. Check missing values and data limitations.
  4. Test safe search and content signals.
  5. Build a transparent baseline ranking.
  6. Perform grouped validation.
  7. Train and evaluate the machine learning model.
  8. Generate ranked recommendations with reason codes.

The notebooks and project artifacts are available in the accompanying GitHub repository.
